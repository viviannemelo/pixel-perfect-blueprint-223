Internal Knowledge Base

A searchable base that gathers the company's scattered knowledge in one place — and keeps itself up to date.

Uma base pesquisável que reúne em um só lugar o conhecimento espalhado pela empresa — e se mantém atualizada sozinha.

What's inside

The base gathers knowledge that used to be scattered across the company into one place. Today it holds about 10,000 searchable records:

  • About 3,000 excerpts from help articles, split by section, so each question finds the exact excerpt that answers it.
  • About 4,300 resolved support tickets, closed cases only. Personal data is removed before anything is stored.
  • About 2,900 records of tasks and fixes from the technical team.
  • Learned answers: replies the team approved that become reference for similar cases.

On top of that there is a layer designed for people. The roughly 470 help articles are being organized into 17 modules, one per product area. Each module follows the same format:

  • Summary in plain language
  • Key terms explained
  • Frequently asked questions with step-by-step guides
  • Short demonstration videos
  • Links to the original sources

Three modules are ready, one is in progress and the other thirteen are planned.

How it keeps itself up to date

  • Every day, each source is re-read automatically. Only what changed is processed again; the rest stays as is.
  • New tickets enter as soon as they are closed. Reopened ones leave until they are resolved again.
  • Task status is checked live whenever a task is used in an answer, so nothing outdated is ever cited.
  • Every night, a test runs with real questions and measures whether the base still finds the right document. If quality drops, the team is notified.
  • Twice a day, a health check inspects every source. It alerts the team if one becomes stale, suddenly loses records or stops working.
  • In the people-facing modules, when a help article changes, the corresponding module is flagged for review. The new version is generated automatically and only published after someone on the team approves it.

What it solves

  • One answer per question. Before, the same question could get different answers depending on where you looked or who replied.
  • Faster support. The team finds the answer and its source in seconds, without searching across several systems.
  • Onboarding new people. Newcomers learn the product through organized modules instead of relying on colleagues' memory.
  • Automations aligned with the team. Reply drafts, alert triage and internal tools query the same base people do, so everything follows the same standard.
  • Privacy. Customer data never enters the base.
  • Trust. Since quality is measured every night and problems raise alerts, the base doesn't silently decay.

O que tem dentro

A base reúne o conhecimento que antes ficava espalhado pela empresa em um só lugar. Hoje ela tem cerca de 10 mil registros pesquisáveis:

  • Cerca de 3 mil trechos de artigos de ajuda, divididos por seção, para que cada pergunta encontre o trecho exato que a responde.
  • Cerca de 4.300 atendimentos já resolvidos, só casos encerrados. Os dados pessoais são retirados antes de qualquer coisa ser armazenada.
  • Cerca de 2.900 registros de tarefas e correções do time técnico.
  • Respostas aprendidas: respostas que o time aprovou e que viram referência para casos parecidos.

Por cima disso há uma camada pensada para pessoas. Os cerca de 470 artigos de ajuda estão sendo organizados em 17 módulos, um por área do produto. Cada módulo segue o mesmo formato:

  • Resumo em linguagem simples
  • Termos-chave explicados
  • Perguntas frequentes com passo a passo
  • Vídeos curtos de demonstração
  • Links para as fontes originais

Três módulos já estão prontos, um está em andamento e os outros treze estão planejados.

Como ela se atualiza sozinha

  • Todo dia, cada fonte é relida automaticamente. Só o que mudou é processado de novo; o resto fica como está.
  • Atendimentos novos entram assim que são encerrados. Os que forem reabertos saem até serem resolvidos de novo.
  • O status das tarefas é conferido ao vivo sempre que uma delas é usada numa resposta, para nunca citar algo que já mudou.
  • Toda noite, um teste roda com perguntas reais e mede se a base ainda encontra o documento certo. Se a qualidade cair, o time é avisado.
  • Duas vezes por dia, uma verificação de saúde confere cada fonte. Ela alerta o time se alguma ficar desatualizada, perder registros de repente ou parar de funcionar.
  • Nos módulos para pessoas, quando um artigo de ajuda muda, o módulo correspondente é marcado para revisão. A nova versão é gerada automaticamente e só é publicada depois que alguém do time aprova.

O que ela resolve

  • Uma resposta só para cada pergunta. Antes, a mesma pergunta podia ter respostas diferentes dependendo de onde se procurava ou de quem respondia.
  • Atendimento mais rápido. O time encontra a resposta e a fonte em segundos, sem procurar em vários sistemas.
  • Integração de pessoas novas. Quem chega aprende o produto por módulos organizados, em vez de depender da memória dos colegas.
  • Automações coerentes com o time. Os rascunhos de resposta, a triagem de alertas e as ferramentas internas consultam a mesma base que as pessoas. Assim, tudo segue o mesmo padrão.
  • Privacidade. Dados de clientes nunca entram na base.
  • Confiança. Como a qualidade é medida toda noite e os problemas geram alerta, a base não se deteriora em silêncio.

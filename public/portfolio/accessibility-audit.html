Accessibility Audit

A screen-by-screen accessibility survey of web and mobile, turned into a single prioritized WCAG report that guides fixes and re-tests.

Um levantamento de acessibilidade tela por tela, na web e no mobile, transformado em um único relatório WCAG priorizado que orienta correções e retestes.

How it works

  • Survey — QA walks through the web platform and the mobile app, screen by screen, looking for accessibility barriers: low-contrast text, buttons with no name for screen readers, invisible keyboard focus, touch targets that are too small and images without alternative text.
  • Report — every problem is recorded in a single report with the screen where it appears, the WCAG rule it violates and its severity (High, Medium, Low).
  • Handoff — the report goes to the development team, and each item becomes a ticket ready to be fixed.
  • Validation — when the fixes arrive, QA uses the report itself to re-test. Each fix is checked directly against a known, documented problem.

What this solves

Before, accessibility problems showed up scattered, in the middle of other tests. Every re-test started with a new hunt: find the problem, document it, and only then validate it. With the centralized survey, each problem is found and described only once. The dev team receives the full, prioritized scope, and QA validates fixes following a known list. This shortens validation time and keeps any item from slipping through unnoticed.

Como funciona

  • Levantamento — o QA percorre a plataforma web e o aplicativo mobile, tela por tela, procurando barreiras de acessibilidade: texto com contraste baixo, botões sem nome para leitores de tela, foco invisível na navegação por teclado, áreas de toque pequenas demais e imagens sem texto alternativo.
  • Relatório — cada problema é registrado em um único relatório com a tela onde aparece, a regra WCAG que viola e a severidade (High, Medium, Low).
  • Reporte — o relatório vai para o time de desenvolvimento, e cada item vira um ticket pronto para ser corrigido.
  • Validação — quando as correções chegam, o QA usa o próprio relatório para refazer o teste. Cada correção é conferida diretamente contra um problema já conhecido e documentado.

O que isso resolve

Antes, os problemas de acessibilidade apareciam de forma solta, no meio de outros testes. Cada reteste começava com uma nova busca: achar o problema, documentar e só então validar. Com o levantamento centralizado, o problema é encontrado e descrito uma única vez. O time de dev recebe o escopo completo e priorizado, e o QA valida as correções seguindo uma lista conhecida. Isso reduz o tempo de validação e evita que algum item passe despercebido.
